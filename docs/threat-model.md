# Внутренняя модель угроз safegamingOS

> ⚠️ **НЕ для красной команды.** Это внутренняя карта слабых мест. Красная
> команда получает `docs/red-team.md` (цель и правила, без списка векторов).

Обновлено после раунда v0.9.8 (аудит blue team: закрыт root-RCE через конфиг инсталлятора `source`, IPv6-обход hosts-блокировки, разблокировка-всего-сразу, GUI читает базу через root-помощник). Раунд v0.9.7: hosts-инъекция через URL загрузки, коллизия per-room UID, межкомнатный kill по префиксу имени, SQLi-экранирование, `--machine-id` не ломает звук игровым комнатам. Раунд v0.9.9 (UX): вход в ОС полностью без пароля — автовход SDDM (группы `autologin`/`nopasswdlogin`, секция `[Autologin]` c `Relogin=true`) в live и установленной системе; у `live` пароль удалён (`passwd -d`), пароль установленного пользователя остаётся только для sudo. Раунд v0.10.0: **офлайн-установка** — полный набор пакетов установки + базы репозиториев + keyring зашиты в ISO (`/opt/sg-offline`); инсталлятор: интернет есть → pacstrap, нет → установка из ISO по локальным базам (`pacman -S` без сети). ⚠️ Раунд v0.11.1 (баг-фикс): в v0.10.0/0.11.0 набор в ISO **не попадал** — он скачивался в customize_airootfs.sh (внутри chroot, где pacman без сети: pacstrap качает на хосте), `pacman -Sy` молча падал (`|| true`), и сборка уезжала без `/opt/sg-offline` (установка без интернета падала на pacstrap — реальный отчёт пользователя). Фикс: набор строится **на хосте** в build_iso.sh (`archiso/airootfs/opt/sg-offline`), customize только проверяет READY и **падает**, если набора нет; в офлайн-установку добавлено копирование mirrorlist в таргет (pacman падал на `Include = /etc/pacman.d/mirrorlist` без файла). Раунд v0.11.0: **автообновление** — GitHub Releases (ISO + слой `safegamingos-files-<ver>.tar.zst`); `sg-update` (check/download/upgrade/apply/rollback) проверяет релизы по HTTPS, уведомляет через KDE, устанавливает с подтверждением пользователя только слой safegamingOS (резервная копия + откат), пакеты Arch — только по явному согласию (`pacman -Syu`). Доверие = GitHub + владелец репозитория (та же модель, что и у самого ISO); файлы-слой ограничены фиксированным списком путей из airootfs. ⚠️ Раунд v0.11.2 (инсталлятор, фикс по реальному отказу): 🔴 **проверка прав конфига была сломана с v0.9.8** — bash-арифметика `$(( conf_mode & 022 ))` парсила `conf_mode` (напр. «600» из `stat -c %a`) как ДЕСЯТИЧНОЕ (нет ведущего нуля), а `022` как восьмеричное (18) → `600 & 18 = 16 ≠ 0` → установка через GUI падала на ЛЮБОМ конфиге с «конфиг не должен быть записываемым для группы/всех — отмена» (реальный отчёт пользователя; баг блокировал все GUI-установки с 0.9.8). Фикс: явное восьмеричное основание `8#${conf_mode} & 8#022`; бонус — root-помощник сам затягивает случайно открытые права до 600 вместо отказа (владелец проверен выше, конфиг по-прежнему только строго разбирается — ужесточение безопасно; на ФС без поддержки прав chmod не сработает и отказ останется) + принят root-owned конфиг — чинит текстовый установщик `sudo sg-install` (раньше падал на проверке владельца: файл пишет root-скрипт, а проверка шла против SUDO_USER). Red-team тест «файл 0666 → отказ» обновлён: 0666 → затягивается до 600 и установка продолжается; «файл чужого пользователя» → по-прежнему отказ.

## Принципиальный предел (честно)

С v0.9.3 **изолированные комнаты** (все типы, кроме browser/games/streaming)
работают от собственного системного пользователя `sgroom-<slug>`: чужие
`/proc`, `/dev/shm`, сокеты `/run/user` и файлы других UID закрыты ядром
(а не чёрными списками), плюс AppArmor-профиль `firejail-default` как MAC-слой
поверх firejail. Это уже «изоляция ядром», а не только списками.

**Комнаты browser/games/streaming остаются от пользователя сессии** — им нужны
PipeWire-сокет (звук), сессионная шина (порталы) и экран. Это осознанный
продукт-трейдофф: браузер — главная точка входа загрузок, и его изоляция —
это firejail (`--private` home, без session D-Bus, `--apparmor`) + модерация
Wayland для экрана/клавиатуры + hosts-блокировка источников (DoH принудительно
выключен политикой Firefox). Абсолютная граница на уровне ядра для
session-комнат не обещается — обещается для изолированных.

## Чек-лист перепроверки (v0.9.5, в VM)

```bash
sudo sg-room-run redteam -- bash    # внутри комнаты:
# echo x > /dev/shm/f               → приватный tmpfs комнаты, исчезает вместе с ней
# ls /dev/shm                        → пусто (не хост-каталог)
# echo x > /run/user/$(id -u)/f     → изолированная комната: каталога нет → ошибка
# ls /var/lib/sg-rooms              → закрыто (blacklist)
# cat /var/lib/sg-rooms/sg.db       → нет доступа
# sudo / pkexec / su                → нет файла (blacklist)
# dbus-send --system ... ListNames  → ошибка
# dd if=/dev/zero of=/var/tmp/x     → нет доступа
# ipcs                              → отдельный namespace (пусто)
# stress --cpu 4                    → упор в CPUQuota, хост жив
# curl https://webhook.site/x       → в не-сетевой комнате: ошибка (нет интерфейса)
# python3 -c 'import ctypes,os; ...process_vm_readv...' → EPERM (seccomp)
# /usr/bin/passwd                  → работает, но привилегий не даёт (--nonewprivs)
# setpriv --reuid 0 true            → не сработает (no_new_privs)

# polkit-RCE (v0.9.5): попытка подсунуть свой скрипт
printf '#!/bin/sh\nid > /tmp/pwned\n' > /tmp/sg-evil && chmod +x /tmp/sg-evil
pkexec /tmp/sg-evil                → DENIED (не в allowlist); /tmp/pwned не создаётся
pkexec /usr/local/bin/sg-room-run browser -- /bin/true  → ок (легитимный)
```
