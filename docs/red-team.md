# Red Team / Blue Team — челлендж safegamingOS

Ты — красная команда. Перед тобой изолированная «комната» safegamingOS.
Твоя задача — сломать изоляцию. Защитник (я) получает твой исходник,
разбирает его статически и патчит защиту. Цикл повторяется.

## Цель (прямая)

Запусти свой код **внутри комнаты** и добейся хотя бы одного из:

1. **Побег (файлы)** — достать файл, которого в комнате быть не должно:
   - содержимое домашнего каталога другого пользователя или другой комнаты,
   - любые системные секреты: ключи, пароли, базы, конфиги вне комнаты.
2. **Слежка** — прочитать, что происходит в других комнатах или на хосте:
   - содержимое экрана других приложений,
   - нажатия клавиш или ввод в другие приложения,
   - звук/микрофон других комнат,
   - список чужих процессов/открытых файлов с полезными данными.
3. **Управление** — заставить систему сделать что-то за пределами комнаты:
   - выполнить команду от имени хост-пользователя или root,
   - изменить файлы системы или других комнат,
   - открыть сокет/сервис хоста, достучаться до других комнат по сети.
4. **Выживание** — после «лечения» комнаты (карантин / удаление) остаться в
   системе: файл вне комнаты, автозагрузка, копия в другой комнате.
5. **DoS честно** — обрушить хост целиком (не только свою комнату).

## Что НЕ считается победой

- Читать то, что комната имеет право видеть: интернет, свой home, свой экран.
- Уговаривать пользователя ввести пароль в диалоге — социальная инженерия на
  пользователя запрещена (это не атака на изоляцию).
- Векторы, требующие физического доступа или root ДО запуска комнаты.
- «Запустил sudo внутри комнаты» — админ-инструменты в комнатах отключены по
  дизайну; их наличие в комнате — не побег, а срабатывание защиты.

## Правила

- Код сдаётся **исходником** (текстом в чат или файлом в `samples/`).
  Бинарники не нужны: защитник разбирает код статически, ничего не запуская
  в своей среде.
- Тестируешь **только в виртуалке**, со снимком до запуска. После каждого
  прогона — откат на снимок.
- Версионируй образцы: `samples/escape-01.sh`, `escape-02.sh`, ... Один файл —
  одна атака. Комбинируешь — пиши это явно.
- Если не знаешь, как устроены комнаты — попробуй догадаться: часть задания
  в том, чтобы самому найти границы. Подсказок защитник не даёт.

## Как запустить образец в комнате

```bash
sudo sg-room-run redteam -- bash
# внутри комнаты (в bash):  bash /путь/к/образцу.sh
```

Комнат несколько типов. Разница между ними — тоже часть задания: выясни,
какая комната для чего, и бей ту, что интереснее.

## Формат ответа защитника

1. **Вердикт**: `CONTAINED` (не вышло) или `ESCAPED` (нашёл вектор) — с
   доказательством: какой файл/экран/команда и каким путём.
2. **Разбор**: 2–5 строк, что код делает.
3. **Патч**: если вектор реален — закрывается, с инструкцией «как
   перепроверить».
4. Повторная атака на уже закрытый вектор — ответ короткий: чем закрыто,
   без спойлеров остального.

## Чего защитник тебе НЕ даёт

Карту слабых мест. Известные проблемы ведутся отдельно, внутри проекта
(`docs/threat-model.md`), и красной команде не показываются. Если защита
стоит — она стоит без подсказок. Единственное, что можно получить:
вердикты по своим образцам и патчи.

## Стенд (для прогона)

- VM: VirtualBox/QEMU, снимок `clean` до первого запуска.
- После каждого прогона: откат на снимок → сверка, что система не тронута
  (`sha256sum` файлов, которые пытался достать).
- Логи для анализа: `sudo sg-av live`, `sudo sg-rooms`, `journalctl -b`.
